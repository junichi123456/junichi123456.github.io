# 対戦中の判断と学習

構築は `pokechamp/tool/team.py`、判断エンジンは `pokechamp/tool/battle.py`、学習は `pokechamp/tool/learn.py`。

## チャットへの出力ルール（厳守）

対戦中のチャットには次の2行だけを書く。理由・計算・補足は書かない。

```
選出順：A → B → C
次に何をするか：<技名 / ○○に交代 / メガシンカ＋技名>
```

## 自動進行モード（ユーザーのチャット不要・推奨）

ユーザーが `python game_watch.py --password <OBSのWebSocketパスワード>` を起動していれば（`pokechamp/logs/live/game_state.json` が数秒以内に更新されている）、次のループで進める。ユーザーにチャットや合図を求めない。

1. `cd pokechamp/tool && python wait_event.py` を **バックグラウンド実行**（run_in_background）して待つ。終了すると自動で起こされる。`--after` は付けない（前回渡したイベントの続きから待つので、判断している間に次の画面が来ていてもすぐ返る。出力の `missed` が1以上なら、その間に画面を飛ばしているので最新の画面で判断する）。
2. 出力 JSON の `phase` で分岐し、`image`（その瞬間のゲーム画面）を Read で読む:
   - `preview`（選出画面）: 選出はイベントの `image`（選出画面の最初の1枚）だけで判断する。選出画面の間も `preview_frames`（`game_NNNN_preview_*.png`）に撮り続けているが、選出には使わない（最初の1枚が読めないときだけ参照）。
     相手の名前は表示されない（3Dモデルの小さな絵とタイプアイコンのみ）。
     イベントの `identify`（各枠のタイプ判定と候補）と `identify_sheet`（左端=画面の枠、右=候補の HOME 3Dモデル画像）を Read で見て、6体を見比べて確定する。
     タイプは必ず `identify` の判定（アイコンの記号の形で判定）を使い、色で推測しない。特に **どく=紫地に丘と丸**、**むし=黄緑地の記号**、**ゴースト=紫地のおばけ** は見間違えやすい。
     候補に一致する絵が無いときだけ、別タイプの読み違いを疑って `python identify.py <画像>` を再実行する。
     **先にイベントの `auto_select` を見る**: 過去の対戦で記憶した絵（sprites.py）と6枠すべてが一致した場合は、game_watch.py が `battle.py select` まで済ませているので、その「選出順」をそのまま出力する（画像は読まない）。
     `sprite_match` で一致した枠（name があるもの）はその名前で確定し、残りの枠だけ下の手順で特定する。
     確定したら `python battle.py select <6体>` を**上の枠から順に**並べて実行し「選出順」を出力（この順で各枠の絵を記憶し、次から即座に特定できるようになる）。
     対戦後、相手6体のタイプが確定したら（判定が違っていた場合は特に）
     `python identify.py <その選出画面の画像> --learn <枠1のタイプ> ... <枠6のタイプ>`（複合は「むし/みず」）で
     実画面のアイコンを学習させる。未学習のタイプ（あく・ドラゴン・こおり）が出たら必ず学習させる。
   - `start` / `command` / `replace`（行動選択画面。`start` は1ターン目（最初の行動選択画面で出る。選出確定後の待ち時間に相手の先発候補ごとの1ターン目を先読みしてあるので、ほぼ即座に判断が出る）、`command` は2ターン目以降、`replace` は自分のポケモンがひんしになった後、またはボルトチェンジ・とんぼがえり・クイックターン等で交代するときの「次に出すポケモン」の選択画面。`replace_mode` が faint / pivot。画面の判定は名前欄の位置で行う: 名前欄が高い位置＝選出画面、少し低い位置＝交代画面。交代画面が「ポケモン」ボタンから開かれずに出たときだけ `replace`。自分でポケモン一覧を見ているだけのときは出ない）:
     **イベントの `decision.decision`（例「次: ロトムに交代」「次: アシレーヌを出す」）をそのまま「次に何をするか」として出力する。画像は読まない・考え込まない。**
     game_watch.py が画面の文字（場の2体の名前・自分のHP「157/157」・相手のHP「100%」）と記録（場の状態・控えのHP）から
     `battle.py auto --screen` で計算済み（画面が出てから通常の場面で約7秒）。ユーザーも game_watch.py のウィンドウで同じ答えを先に見られる。
     `decision` が null・失敗のときだけ、画像（`image`）から場の2体とHPを読んで `python battle.py auto --hp <自分> <相手%> --me <名前> --opp <名前>` を実行する。
     `decision` が場と合わない（倒れたポケモンへの交代・場にいないポケモンの技・メガシンカ済みなのに再びメガシンカ）ときも画像を読み、
     倒れたポケモンを `--fainted ルカリオ,クチート` で渡して同じコマンドを実行する。
     state.json は書かない・learn.py turn も呼ばない（auto がターンの記録も行う）。
   - 対戦中の画面は `pokechamp/logs/live/frames/<選出のイベント番号>/` に0.5秒ごとに保存されている。HPが読めないときだけ数枚見て補う。
     メッセージの読み取り結果は `pokechamp/logs/live/battle_messages.jsonl` に残る。抜き出しに失敗している言い回しは対戦の合間に `msgparse.py` を直す。
   - `timeout`: 何も出力せず 1 に戻る。
3. 出力したら **すぐに 1 に戻って** 次を待つ。対戦終了（勝敗画面）を画像で確認したら `learn.py end` で記録し、そのまま次の対戦を待つ。
4. 行動はイベントを受け取ったら即出力する（判断は game_watch.py が画面表示から通常の場面で約7秒で計算済み。行動は45秒、選出は90秒の制限）。

## 手順

0. **観測は game_watch.py だけを使う**（PCBL・pcbl_watch.py は使わない）:
   ユーザーが `python game_watch.py --password <OBSのWebSocketパスワード>` を起動し、OBS の映像から選出画面・行動選択画面・戦闘メッセージ・0.5秒ごとのフレームを取得する。
   判断は上の「自動進行モード」で `wait_event.py` のイベントを受けて行う。ユーザーにスクリーンショットや画面の説明を求めない。
   **時間制限**: 選出は `battle.py select`（約3〜10秒）、各ターンは `battle.py auto --hp …`（通常の場面で約7秒）。画像読み取りを含め10秒以内に答える。
1. **開始前**: `pokechamp/logs/TRENDS.md` と `pokechamp/logs/COUNTERS.md`（公開構築ごとの事前対策）を読み、要対策の相手と想定外の型を頭に入れる（チャットには書かない）。
   相手の6体が `pokechamp/tool/data/known_teams.json` の構築と**6体すべて一致したときだけ**、`battle.py select` は事前に計算した選出を返し（「既知構築: …（6体一致）」と表示）、対戦中も記事の型を参考に読む。5体以下の一致は別の構築として扱い、記事は使わない。6体一致でも、記事と違う技・持ち物・メガが1つでも見えたら別人の構築とみなし、全員について記事の情報を捨てて通常の推定に戻る（記事の参照でプレイングを歪めない）。
   ユーザーから構築記事（pokesol）のURLを渡されたら `python pokesol.py <URL>...` で取り込み、`python prep.py` で対策を作り直してコミットする。
2. **見せ合い**: 相手6体が分かったら
   `cd pokechamp/tool && python3 battle.py select <相手6体>`
   → 出力の選出順を伝える（記録 `logs/current.json` が自動で作られる）。実際に選んだ順が違えば `python3 learn.py pick <順>` で直す。
3. **各ターン（型推定を毎ターン必ず行う）**: ターンの結果が分かったら、まず観測つきで記録する:
   `python3 learn.py turn '{"turn":N,"me":"…","opp":"…","my_action":"…","opp_action":"…","first":"me|opp","opp_item":"…","opp_mega":true,"ko":["me|opp"],"obs":[…]}'`
   `obs` には次を毎ターン漏れなく入れる（形式は `infer.py` 冒頭）:
   - `dealt`: 自分の技で相手のHP%が何%→何%になったか（急所・ランク補正・天候も）
   - `taken`: 相手の技で自分が受けた実ダメージ
   - `order`: 同じ優先度の技でどちらが先に動いたか（スカーフ・素早さ配分の判定）
   - `move` / `item` / `ability` / `mega`: 判明したもの
   次に state.json を作り（形式は battle.py 冒頭）、
   `python battle.py turn state.json`
   画面から分かれば state.json の各ポケモンに `last_move`（こだわり固定）・`rampage`・`sub`・`glaive`・`toxn`、全体に `trick_room`（残りターン）を書く（省略時は field_state.json から補完）。まきびし・どくびし・ねばねばネット・壁・おいかぜは `cond_me`/`cond_opp`、じゅうりょく・マジックルーム・ワンダールームは `pseudo` に書く。
   → 出力の行動を伝える。battle.py は `logs/current.json` の観測を自動で読み、候補（使用率258種の持ち物×性格×能力P、データが無ければ種族値からの役割推定）の事後確率を更新し、最も確からしい型で、Showdown準拠の engine.py 上で5ターン木＋ロールアウトの計8ターン先まで読む（search.py、全CPUコア並列）。
   推定が割れているときは `python3 battle.py infer <相手>` で上位候補を確認してよい（チャットには書かない）。
4. **終了**: `python3 learn.py end win|lose|draw <負け筋メモ>`
   → `logs/battles.jsonl` に追記され、`logs/knowledge.json` と `logs/TRENDS.md` が更新される。
5. **保存**: ログをコミットして push する（`pokechamp/logs/`）。次のセッションはここから学習結果を読み込む。

## 学習が反映される箇所

- 相手の型: 使用率データ（全258種）または役割推定の候補に、過去ログで推定した型・観測した持ち物を事前確率として上乗せし、対戦中の観測でベイズ更新（`sets.py` / `infer.py` / `battle.opp_sets`）。最速でも抜けない相手に先に動かれた回数が2回以上ならスカーフとみなす。
- 相手の選出予測: 見せ合いに出た回数に対する選出率・先発率（`pick_rate` / `lead_rate`）。
- 自分の選出: 過去の「自分のポケモン×相手の選出ポケモン」勝率を小さく加点（`history_bonus`）。

10戦ごとを目安に `python3 learn.py report` の「要対策」を見て、構築（team.py）や技の変更をユーザーに提案する。提案は対戦中ではなく対戦の合間に行う。

- メッセージはメッセージ欄だけを0.25秒ごとに読む監視（MsgWatch）がもれなく記録し、技ごとのダメージから相手の型を自動で絞る（何もしなくてよい）。

## Sonnet で判断するとき（事実パケット）
- `decision.json` の `full` に `PACKET {...}`（facts.py）が付く。ダメージ・確定数・素早さ・相手の型の確率・見落とし警告（warn）は
  Python が計算済み。Claude は計算せず、`pokechamp/tool/SONNET_PROMPT.md` の手順で確率的な判断だけを行い、1行で答える。
- 探索時間は局面で自動（最終局面2秒／通常5秒／分岐が多い9秒）。`--decide-sec` で固定もできる。

## あばれる状態（げきりん・あばれる・はなびらのまい）
- 使うと2〜3ターン同じ技を出し続け、その間は行動選択画面が出ない（game_watch も判断しない）。終わると自分が混乱する。
- 行動選択画面が出た時点で自分のあばれる状態は終わっている。直前の技を継続中とは扱わず、混乱（`confusion`）を前提に判断する。
- 相手があばれる状態のときは、相手の次の技は固定（packet の warn に L: として出る）。

## 交代する技（ボルトチェンジ・とんぼがえり・クイックターン）と強制交代
- 技が成功すると手持ち画面が開き、使用者と場のポケモン以外から自由に選べる（キャンセル不可。時間切れは先頭の控え）。
  交代先は、その後の相手の攻撃を受ける前提で選ぶ（相手が遅いとき）。
- 手持ち画面が開かないとき: 防がれた・外れた・効果なし／控えがいない／ゴツゴツメット・さめはだ等でひんし（ターン終了時に出す）／
  相手のレッドカード（こちらがランダムに交代）／相手のだっしゅつボタン・にげごし・ききかいひ（相手だけが交代）。
  game_watch はこれらをメッセージから見分け、交代の判断を出さない。
- ドラゴンテール・ともえなげ・ほえる・ふきとばし・相手のレッドカードで出される場合、出てくるポケモンはランダムで選べない（判断不要）。

## 画面（シーン）の判定
- `scenes.py` が0.15秒ごとに、色と位置だけで画面を分類する: preview(選出) / party(手持ち一覧) / input(行動入力中) / vs / result / battle(演出) / other。
- 「行動入力中」は右上の「COMMAND ○○ / 様子を見る」の表示で判定する。たたかう・技一覧・状態確認・手持ち確認を開いても同じ1回の入力として扱い、
  1ターンに `command` を1回だけ出す。結果画面では `result` を出す。遷移は `logs/live/scenes.jsonl` に残る。

## 似た並びの記事ガイド（夜間記録）
- 夜間のルーチン（study.py）は、新着構築記事の型・運用・選出基準を `data/known_teams.json` の `guide` に記録する（対戦のシミュレーションはしない）。
- `battle.py select` の出力と、packet の `ref` に、相手の6体のうち3体以上が一致する構築のガイドが「参考」として出る。
  頭の片隅に置く材料であり、見えた技・持ち物・メガが記事と違えば使わない。選出・技の判断は従来どおり実際の盤面で行う。
- 現行レギュレーションは `pokechamp/tool/data/regulation.json`。切り替わると（新レギュレーションの記事が直近7日で8件以上かつ現行より多い）、
  study.py が自動で切り替え、古い構築は `known_teams_archive.json` に移す（消さない）。battle.py は現行の構築だけを見る。手動は `python regulation.py switch <コード> <開始シーズン>`。
- やっくん（yakkun.com）の構築記事は Cloudflare でクラウドから取れないため、PCの `yakkun_fetch.py`（起動時に自動実行）が
  `logs/study/yakkun/*.json` に保存・push する。夜間学習ではそのファイルを読んで取り込み・ガイド作成をする（初回は `_samples/` のHTMLで構造を確認して取り込み処理を作る）。

## 手で決めた選出ルール
- `pokechamp/tool/data/select_rules.json` に「相手に○○がいるとき△△を選出に入れる」を書く。`battle.py select`（game_watch の選出提案も同じ）がその範囲で最善の選出・先発を選ぶ。
- 現在のルール: なし（カバルドン入りでもアシレーヌは強制しない。重点対策の相手として探索に任せる）。
- 記事の型に固定した counter（pinned）がある場合は、そちらを優先する。
- 戦闘メッセージ欄は、ゲームの字体の見本照合（`tool/glyph_ocr.py`・見本は `data/glyph_templates.json`）で先に読み、
  見本が足りない・点数が低いときだけWindows OCRに戻る（`game_watch.py --no-glyph` で無効）。見本は game_watch 起動時に
  `logs/live/msgcrops/` の読み取り結果から自動で増える（手動: `python glyph_ocr.py learn <画像> "<正しい文字列>"`）。
  見本が約150文字を超えるまでは従来どおり。仕様と今後の予定は `pokechamp/SPEC_VISION.md`。
