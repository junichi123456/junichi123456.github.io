# ポケモンチャンピオンズ ダメージ計算・構築診断ツール

Lv50・能力ポイント制（合計66／各32）のダメージ計算機と、構築診断スクリプト。

| ファイル | 内容 |
|---|---|
| `calc.py` | 実数値・ダメージ計算（乱数16段階、4096分率補正チェーン、五捨五超入）、タイプ相性、覚える技の参照 |
| `meta.py` | シーズンM-6使用率上位の採用型（最多採用の性格・能力P・持ち物・技） |
| `team.py` | 構築6体 |
| `keycalcs.py` | 主要ダメージ計算の一覧を出力 |
| `coverage.py` | 1対1簡易判定と、補完枠の総当たり探索 |
| `report.py` | `../index.html`（構築レポート）を `template.html` から生成 |
| `data/` | レギュM-Cで使用可能なポケモン・技・覚える技（damekei.com のデータから抽出） |

```sh
python3 keycalcs.py   # ダメージ計算
python3 coverage.py   # 補完枠探索
python3 report.py     # レポート再生成
```

例:

```python
from calc import Mon, show
a = Mon('メガルカリオＺ', 'おくびょう', dict(hp=2, spa=32, spe=32), 'はどうのぼうご', 'ルカリオナイトZ')
d = Mon('メガボーマンダ', 'いじっぱり', dict(hp=1, atk=32, defn=1, spe=32), 'スカイスキン', 'ボーマンダナイト')
print(show(a, d, 'ラスターカノン', atk_boost=2))
```

## 対戦中の判断（battle.py）

```sh
python3 battle.py select ガブリアス ボーマンダ アシレーヌ セグレイブ カバルドン サーフゴー   # 選出順
python3 battle.py turn state.json                                                       # 次の行動（既定10秒探索。秒数を後ろに書けば変更）
```

- 選出: 相手6体から使用率と相性で相手の選出3体を推定し、自分の全60通り（3体×先発）を engine.py で最後まで対戦させて評価し、上位12通りは自分側1手読みで再評価します（全CPUコアで並列）。
- 行動（search.py）: 1ターン目は自分の全行動×相手の有力4手を、乱数・命中・急所・まひ・追加効果などの確率分岐つきで評価。2〜5ターン目は両者同時選択の木（自分3→2手×相手2手）、6〜8ターン目は双方の最善手ロールアウトで、計8ターン先の局面を評価します（相手は最善応手60%＋平均40%）。既定10秒で通常は5ターン木まで完了し、選択肢が少なければ8ターンすべて木で読みます。
- `state.json` の形式は `battle.py` 冒頭のコメントを参照。Battle Logger のライブ表示（HP%・場のポケモン・使用技）を写して使います。

## 対戦ログの蓄積と学習（learn.py）

対戦ごとに `select → turn（毎ターン記録）→ end` で `../logs/battles.jsonl` に追記されます。`end` のたびに `knowledge.json`（相手ごとの選出率・先発率・観測した技/持ち物・スカーフ疑い、自分の選出別勝率）と `TRENDS.md`（傾向と対策）が更新され、`battle.py` が次の対戦から読み込みます。手順は `.claude/skills/pokechamp-battle/SKILL.md`。

## 相手の型の推定（sets.py / infer.py）

- `sets.py`: シングル使用率データ（gamewith.ai、シーズンM-6、全258種）から「持ち物×性格×能力P配分」の候補を事前確率つきで最大24通り作ります。性格と配分の矛盾（攻撃に振っていないのに攻撃上昇性格など）は確率を下げ、技は配分に合う物理/特殊を優先します。データが無いポケモンは種族値から役割（物理/特殊アタッカー、物理/特殊受け）を判定し、先制技・積み技・回復技・状態異常技・持ち物・メガシンカを含む候補を作ります。
- `infer.py`: 対戦中の観測（与ダメージ%、被ダメージ、行動順、判明した技・持ち物・特性・メガ）で各候補の尤度を計算し、事後確率を更新します。`battle.py` は最も確からしい型で先読みします。
- 過去の対戦で推定した型と観測した持ち物は `learn.py` が `knowledge.json` に蓄積し、次の対戦の事前確率に反映します。

## PCBL（Battle Logger）の画面読み取り（pcbl_watch.py）

PC上で PCBL の Live Scan 画面（`http://127.0.0.1:8000/live`）をブラウザで開き、表示中の文字とスクリーンショットを数秒おきに `../logs/live/` に保存します。PCBL の内部データや通信は読みません。

```
pip install playwright
python pcbl_watch.py            # Edge / Chrome を自動で使う。--headed で表示、--url で別URL
```

`parsed.json` にはポケモン名・HP%・ターン数・技名を拾った結果が入ります（画面の文字から拾う簡易方式）。

## 自動進行（game_watch.py / wait_event.py）

PCBL のライブスキャンは選出画面を拾わないため、OBS が受け取っているゲーム映像を直接見て「選出画面」「自分の行動選択画面」を検出します。

```
pip install obsws-python winsdk pillow pygetwindow
python game_watch.py --password <OBS WebSocketのパスワード>   # OBSのツール→WebSocketサーバー設定
```

- 映像は OBS WebSocket の `GetSourceScreenshot`、文字は Windows 標準の日本語 OCR で読みます。
- 選出画面（「選出してください」）と行動選択画面（自分の技名が2つ以上 or 「たたかう」等）を検出すると `../logs/live/game_events.jsonl` に追記します。
- 対戦中の Claude は `python wait_event.py` をバックグラウンドで実行して待ち、検出のたびに自動で起こされて判断します。ユーザーがターンごとにチャットを送る必要はありません。
- `python battle.py types ほのお かくとう` で、タイプの組み合わせから相手の候補を使用率順に出せます（選出画面は相手の名前が出ないため）。

## 選出画面の相手特定（identify.py）

選出画面では相手の名前が出ず、小さな3Dモデルの絵とタイプアイコンだけが表示されます。

```
python identify.py <選出画面の画像>
```

1. 右列6枠のタイプアイコンを、アイコン内の白い記号の形（`data/type_glyphs.json`）で判定します。色では判定しません（どく・むし・ゴーストなどは色だけだと誤認しやすいため）。黒枠や拡大縮小は自動で補正します。
2. そのタイプの使用可能ポケモンを候補にし、PokeAPI の HOME 3Dモデル画像を並べた照合シート（左端=画面の枠）を作ります。候補は枠の絵と色が近い順に並びます。
3. `game_watch.py` は選出画面を検出すると自動でこれを実行し、結果をイベントに含めます。
4. 実際のゲーム画面のアイコンは学習できます: `python identify.py <選出画面> --learn むし/みず じめん エスパー/ノーマル みず/フェアリー いわ/どく ひこう/はがね`（`data/type_glyphs_game.json` に追加。現在 18 タイプ中 15 タイプ学習済み、あく・ドラゴン・こおりは未学習）。

## 戦闘メッセージの解析（msgparse.py）

`game_watch.py` は 0.7 秒ごとの文字認識で、行動選択画面と次の行動選択画面のあいだに流れた戦闘メッセージを集め、`msgparse.py` で次を抜き出します。

- 使われた技と行動順、能力ランクの変化（ぐーんと=±2、ぐぐーんと/がくーんと=±3）
- 天候・フィールドの開始と終了、ステルスロックの設置（どちら側か）
- 持ち物の消費・発動（タスキ、オボン、いのちのたま、ゴツメ、たべのこし、ふうせん、シード類など）
- 状態異常（どく/もうどくを区別し、もうどくの経過ターンも数える）と回復、交代、ひんし、メガシンカ、特性の表示、急所・効果ばつぐん
- トリックルームの開始と終了（残りターン）、みがわりの設置と消滅、各ポケモンの直前の技（こだわり固定・げきりん継続・きょけんとつげき後の被ダメ2倍の判定に使う）

結果はイベントの `turn_events` と、ターンをまたいで累積した `../logs/live/field_state.json` に入り、`battle.py` は state.json に書かれていない項目をここから自動で補います。文言は本編（SV）準拠なので、チャンピオンズでの言い回しに合わない箇所は `battle_messages.jsonl` の生ログを見て `msgparse.py` を調整します。

## 先読みで扱う仕様（engine.py）

- `engine.py` は Pokémon Showdown の Champions ルール（`gen9championsbssregmc`）を Python に移植したシミュレーターです。チャンピオンズに存在する技510・特性216・持ち物166・ポケモン350（メガ含む）を `data/champ.json`（`sd/export_showdown.js` と `sd/build_data.py` で Showdown から生成）から読み込み、行動順（優先度・素早さ・トリックルーム）、ダメージ計算（補正の順番と丸めまで）、ターン終了時処理の順番、交代時の処理、天気・フィールド・壁・設置技・トリックルーム等の場の状態、状態異常・ひるみ・こんらん・メロメロ等、チャンピオンズ独自仕様（まひの行動不能1/8、ねむり2〜3ターン、こおり最大3ターン、PP、アンコールの即時反映、新メガ特性など）を再現します。
- 検証: `sd/difftest.py` が Showdown 本体（`sd/oracle.js`）と同じ乱数方針で同じ対戦を12ターン進め、毎ターンのHP・状態・能力ランク・持ち物・場を比較します。使用率上位の型同士で99〜100%、全習得技・全特性・全持ち物からランダムに組んだ型同士でも約99%の対戦が12ターン完全一致します（残りは非常にまれな組み合わせ）。
- 確率: 1ターン目はダメージ乱数（倒せる/倒せない）、命中、急所、まひ、追加効果、ねむり・こおりのターン数などの分岐を確率つきで評価し、2ターン目以降は最もありうる結果で読みます（命中率とまひはダメージの期待値に反映）。
- 1手の計算時間は既定10秒（画像の読み取りを含め13秒以内）。

```
python msgparse.py messages.txt    # 1ターン分のメッセージ（1行1メッセージ）を解析して表示
```
