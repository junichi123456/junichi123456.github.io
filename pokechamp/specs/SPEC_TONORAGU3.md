# SPEC_TONORAGU3: 1匹除外＋ミミッキュ必須＋ムクホーク／リザードンX同時選出可（ムクホークはメガなし）で 6手読みブラインド各10戦

作成: Opus 5.5 / 実装: Sonnet 5.5 / 前提: `specs/SPEC_TONORAGU2.md`（tn2）・`logs/TONORAGU2.md`
対象: `tool/roundrobin.py`（`tonorag` に `--tn3` 系を追加）、`tool/refine.py`（`blind_play` にオプトインのメガ禁止引数だけ追加）
対象外: Star Crusade、game_watch.py、battle.py の実戦判断、engine.py / search.py / playbook.py、tn1・tn2 の既存結果。**実装者は本番（run）を実行しない**（selftest と実測1戦まで）。

## 0. ユーザー要件
- tn2（トノラグ固定選出）の stage1 が全部終わったら、その結果から**リザホーク（`TN_L`）側で最も勝てない1匹を除外**し、残り5体で行う。
- 選出は**ミミッキュ必須**の3体。**ムクホーク＋リザードンXの同時選出を許容**し、その時は**ムクホークはメガシンカしない**（リザードンXがメガ）。
- **6手読みブラインドテストを各10戦**。相手・ケア・プレイブック・リソースは tn2 と同じ（`know=False`、deny `(True, True)`、L側プレイブック既定オン／`--no-playbook`、resource `loose`）。

## 1. 除外する1匹の決定（機械集計）
- 入力: `logs/refine/tn2_games.json` の `stage==1` かつ `res` が None でない全試合（A/B/C・相手選出6通り・24選出すべて）。`tn2_plan.json` の `games['1']` 分（24×6×N1）が揃っていなければ plan は停止（`--exclude` 指定時は停止しないが、根拠表には「tn2 未完（n/総数）」と出す）。stage2 は使わない（再現性のため）。
- 指標（L視点、`tn_score`）: 各個体について **選出された試合（`sel` に含む）の勝率** `rate` を主指標とする。ミミッキュは除外候補から外す（表には載せる）。
- 同率（勝率を 0.1pt に丸めて同じ）の場合の順: ①**実際に場に出た試合**（tn2_logs の L 側の場に一度でも出た）の勝率が低い方 → ②**先発時の勝率**が低い方 → ③**被先頭瀕死率**（その試合で L の最初の瀕死がその個体だった数／選出数）が高い方 → ④構築の並びで後ろの方。
- `--exclude 個体名` で手動指定（6体の base 名のみ可。ミミッキュ・不明名はエラー）。指定時も根拠表は作り、「手動指定（機械決定なら○○）」と併記。
- plan に `exclude: {'name', 'mode': 'auto'|'manual', 'table': [{name, n, rate, ci, n_out, rate_out, n_lead, rate_lead, first_faint, first_faint_rate}], 'tn2_sha256': tn2_games.json のハッシュ}` を保存。
- 注意（レポートにも書く）: 24候補は個体の組み合わせが偏っている（tn2 にムクホーク＋リザードンXは無い）ため、選出時勝率は組む相手の影響を含む交絡あり。参考値（2026-11-13 時点、stage1 896/1152戦）: ガブリアス 39.9%(376)、ムクホーク 40.7%(312)、アシレーヌ 43.5%、リザードン 48.2%、ミミッキュ 51.6%、イダイトウ 66.8% → 現時点ではガブリアス除外だが差は 0.8pt で、完了後に入れ替わり得る。**ムクホークかリザードンが除外された場合は同時選出の論点は発生しない**（メガ禁止は使われず、レポート §4 は「該当なし（○○除外）」）。

## 2. 選出のルール
- 許容集合 `tn3_orders(rt, excl)`: 除外後5体から、ミミッキュを含む3体（ミミッキュ＋残り4体から2体＝6組）×先発3通り＝**18通り**。表記は既存 `norm_order`（先発＋後発2体は構築の並び順）。
- メガ: `all_orders` の「メガ持ち2体以上は除外」は使わず、ムクホーク＋リザードンX（＋ミミッキュ）の3通りも含める。**24通り制約・メガなし4通り制約・mega_split 調整は適用しない**（18通り全部が許容集合。build_candidates は呼ばない）。
- メガ禁止の適用: L の選出が `{'ムクホーク','リザードン'} ⊆ sel` の時だけ L 側の `megaban = ['ムクホーク']`。それ以外は従来どおり（ムクホーク単独ならムクホークがメガ）。

### 2.1 blind_play のメガ制御（refine.py、最小の変更）
- 現状: engine の行動は `('m', 技, mega)` で、`can_mega` が True なら自動でメガする（engine.py `legal_actions` 4099行付近）。個体ごとに禁止する引数は**無い**。さらに `B.engine_game` は **side1 だけ「最初のメガ持ち以外の can_mega を False」** にするため、L が side1（k 奇数）の時は並び順で先のムクホークがメガ可・リザードンXがメガ不可になり、要件と逆になる。
- 追加: `blind_play` の `args[14]` = `megaban`（`(side0 の base 名リスト or None, side1 の … or None)`、省略・None で従来と完全同一）。`st = B.engine_game(...)` の直後に、megaban が指定された側について: base 名が megaban にある個体は `can_mega=False`、それ以外で `mega_form` を持つ個体は `can_mega=True`（engine_game が落とした分の復元）。RNG は触らない。
- 呼び出し側は `args[12]`/`[13]` が空でも位置を埋める（`(None, None)`）。base 名の取り方（`B._base(m.name)` か `m.base_form`）は実装者が確認して1か所の関数 `_mega_ban(st, side, names)` にまとめる。
- L 自身の読み（`belief(st, 1, …)`）は真の st を複製するので禁止がそのまま効く。**相手の読み（`belief(st, 0, t_me, …)`）は禁止を知らない**（ブラインド。相手はムクホークのメガも警戒しうる）。これを既定とし、レポート §1 に明記。
- プレイブック p1/p2 の `who: メガムクホーク` は base 名一致（playbook.py 449行）なので、メガしないムクホークにも適用される。そのまま使い、§1 に注記。resource の軸（リザードン・ムクホーク）も変更しない。

## 3. 6手読みブラインドテスト「各10戦」の定義
- 単位（セル）: **変種(A/B/C) × 相手選出**（tn2 と同じ `tn_opp_sels(V, rt, TN2_LEADS)`＝先発 イエッサン／バサギリ／イエッサン♀、後発 ニョロトノ→ラグラージ／ラグラージ→ニョロトノ）＝6セル、**各セル 10戦（k=0..9）、計60戦**。k の偶奇で左右入れ替え（偶数 L が side0、既存 `tn_job` と同じ）。
- 種 `crc32(f"tn3{V}{'/'.join(osel)}{k}")`（L選出を含めない＝同じ k は選出が違っても同じ乱数）。key `tn3:{V}|{osel}|{k}`。
- 深さ: **自分6手・相手6手（(6,6)、既定）**。tn 系は両側同深さで、6手読みの指定は両側に掛けるのが公平なため。`--opp-depth 4` で (6,4) にもできる（plan の sig に含む）。
- **L側の選出（推奨＝`--sel adapt`、既定）**: 既存 `adapt_select` を18通りに対して使う。セル内で k 順に逐次決定し、履歴 `hist` はそのセルの過去試合（`{'n','mine','theirs': norm_order(osel),'res_for_A'}`）。
  - 理由: 60戦では18通りを順に試すと1通りあたり平均0.55戦/セル・3.3戦/全体で何も言えない。適応選出なら勝てる選出に試合が集まり「このルールで実際にどれだけ勝てるか」を直接測れる。相手は固定選出なので履歴が効く。
  - 準備: L のチームを複製し `candidates`＝18通り、`article_orders`・`gitems[*].orders` を18通りとの共通部分に絞る（空の項目は落とす）。第1戦用 `decide_pair` の結果は plan 時に変種ごとに計算して `plan['sel1']` に固定。
  - adapt 内の評価試合（`_ad_val`→`B._game_job`）にもメガ禁止を効かせる: tn3 実行中だけ `_AD_EVAL` に「engine_game → `_mega_ban` → `search.play(smart)`」を入れる（終了時に戻す）。
  - 記録: `sel`、`sel_why`（adapt の戻り値）、`mr_best`（ムクホーク＋リザードンXを含む選出で adapt の期待値 `e` が最大のものとその値、選ばれた選出の `e`）。
  - 代替 `--sel rotate`: 18通りを `orders[(k + 3*cell_index) % 18]` で順に使う（逐次依存なし、網羅寄り）。
- 任意の対照 `--control`: 各セルで tn2 の最良選出（変種ごと: stage2 があれば stage2 勝率、無ければ stage1 勝率→平均残HP 順の1位）を同じ種・同じ深さで10戦（key `tn3c:…`、+60戦）。既定はオフ。
- 並列: 選出が逐次依存なので「ラウンド k ごとに6セルを並列」（選出決定＋試合を1ジョブにまとめてワーカーで実行）。procs は 6 を超えても速くならない。

## 4. 時間・保存・再開
- 実測: d4 平均 10.9秒（tn2 実績）、d5 は見積り57秒（tn1 実績 30.4秒）。1手増えるごとに約2.8〜5倍 → **d6(6,6) は 1戦 約90〜290秒、中央 約180秒**と見積もる。adapt の選出決定は1回 約10〜30秒（plan/selftest で実測して表示）。
- 全体: 10ラウンド × ceil(6/procs) 波 × (試合＋選出)。procs=4: 20波×約200秒 ≒ **約67分**（rf=1.3 で約87分）、procs=6: 約33〜44分。`--control` 付きはほぼ2倍。(6,4) はおよそ4割減。plan は実測1戦（selftest の実 d6 1戦の秒数があればそれ、無ければ180秒）で見積りを出し、180分超なら警告（止めない）。
- 保存: `tn3_paths(out_dir)` = `logs/refine/tn3_plan.json`、`tn3_games.json`、`tn3_logs.jsonl`、`logs/TONORAGU3.md`（`--out-dir` 時はその中）。1戦ごとに `safeio.write_json` で atomic 保存、ログは tn2 と同形式（`{'key','log','snap','post'}`、SNAP オン）で追記。
- 再開: 再実行時は各セルで「k 順に最初の未完（無い／error）」から再開し、`hist` は保存済みの試合から再構成。前の k が error のセルはそこで止まり、`--retry-errors` で再実行。`--games` を増やすと新しい k だけ追加。選出は同じ hist から決定的に同じになること。
- **既存結果は読むだけ**: tn_*・tn2_*・TONORAGU.md・TONORAGU2.md は書かない。

## 5. レポート `logs/TONORAGU3.md`
1. **条件**: 深さ・N・sel 方式・deny・resource・playbook 署名・種の式・相手選出表・メガ禁止の扱い（相手は禁止を知らない、playbook の who 注記）・見積りと実所要（sec 合計/procs）。
2. **除外した個体と根拠**: §1 の表（全6体、n・勝率・Wilson 区間・出場時・先発時・被先頭瀕死率）、決定方法（auto/manual）、同率判定の有無、tn2_games.json の sha256、交絡の注記。
3. **選出別・変種別の勝率**: 変種×相手選出（後発順2通り）ごとの通算勝率と区間、L選出ごとの試合数・勝率（n<5 は「（参考）」）、adapt が選んだ選出の推移（k=0..9）。
4. **ムクホーク＋リザードンX同時選出**: 該当試合数・勝率、ムクホークの働き（場に出たターン数、与えた倒し数＝faints の倒した側の場、いのちがけ使用回数と直後の相手瀕死、被瀕死ターン）、リザードンXのメガターン、ムクホークが一度もメガしていないことの確認行、`mr_best` の期待値と選ばれた選出との差（adapt が選ばなかった理由の目安）。該当0件は「該当なし」。
5. **ミミッキュ必須ルールの効果**: 変種ごとに tn3 勝率と tn2 最良選出の勝率（tn2 の深さを明記）を並べ、差と区間。`--control` があれば同深さの対照との差を主に示し、無ければ「深さが違うので参考」。
6. **勝ち筋のターン別行動**: tn2 と同形式（`tn2_items`/`tn2_points` を流用: T1〜T6 の L・相手の（場,行動）上位3、分岐点、個別論点、推奨手順は「シミュレーション由来・仮説」）。対象は最多選出と、同時選出の試合。
7. **結論**: 変種ごとに1行（選出・勝率区間・要点）。

## 6. 受け入れ条件（`python3 roundrobin.py tonorag selftest --tn3` で全部 OK）
1. `python3 -m py_compile tool/roundrobin.py tool/refine.py` が通る。`tonorag selftest`（tn1）と `tonorag selftest --focus`（tn2）も従来どおり全部 OK。
2. **除外個体**: スタブ games で手計算どおりの個体が選ばれる。ミミッキュが最低でも除外されない。同率のスタブで ①→④ の順に決まる。`--exclude ガブリアス` が優先され、`--exclude ミミッキュ`／存在しない名前はエラー。tn2 stage1 未完なら `--exclude` 無しの plan は停止。実データ（完了時）の決定結果を表示。
3. **ミミッキュ必須**: 許容集合が18通り、全てにミミッキュを含み除外個体を含まない、3体重複なし、`norm_order` 済み。除外がムクホーク・リザードン以外なら同時選出が3通り含まれる。全ジョブの `sel` が許容集合内。
4. **ムクホークがメガしない**: 実 `blind_play` 浅い深さ (1,1) で、同時選出（ムクホーク先発）を k 偶数・奇数の両方で1戦ずつ → log にムクホークの `M+` が一度も無く、snap でムクホーク場の時は `mega` が立たない、開始時にリザードンXの `can_mega` が True（両方の parity）。同じ種で megaban 無しなら k 偶数でムクホークがメガする（禁止が効いていることの対照）。megaban 無しの従来呼び出しは同じ種で res/log/faints/left/turns が変更前と一致。`_AD_EVAL` フックでも禁止が効く。
5. **再開**: スタブ（`_TN_PLAY` と選出を差し替え）で一部実行→再実行で残りだけ、セル内は k 順、error のある k より後は走らず `--retry-errors` で再開、同じ hist から同じ選出。
6. **既存結果不変**: selftest 前後で `logs/refine/tn_plan.json`・`tn_games.json`・`tn_logs.jsonl`・`tn2_plan.json`・`tn2_games.json`・`tn2_logs.jsonl`・`logs/TONORAGU.md`・`logs/TONORAGU2.md` の sha256 が一致（selftest は一時 out-dir のみ）。
7. report: スタブから TONORAGU3.md（一時 out-dir）が §5 の1〜7の見出しを全部持つ（該当0件は「該当なし」）。
8. 時間: 実 d6 1戦（(6,6)、同時選出、本番 out-dir には書かない）と adapt 選出1回の秒数を表示し、plan の見積り（procs=4）を表示。本番 run はしない。
