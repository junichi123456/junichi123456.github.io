# 交代を繰り返す・勝てる対面で引く 不具合 修正仕様書

作成: Opus 5.5 / 実装: Sonnet 5.5

## 症状（ユーザー報告）
- 自分アシレーヌ vs 相手メガルカリオZ。相手が先手でラスターカノンを撃ち、アシレーヌは半分以上残った。こちらのムーンフォースで相手を約6割削った。
- 次のターンはムーンフォースで対面に勝てる（相手の残りHP約40%に対してムーンフォースは確定1発。相手の既知の技ラスターカノンではアシレーヌは落ちない）。
- それなのに「ミミッキュに交代」を推奨し、次のターンは「アシレーヌに交代」を推奨した。
- 正しい考え方: 勝てる対面ではアシレーヌで殴る。アシレーヌを切り気味に使ってもよい。ミミッキュのばけのかわは最後の1対1まで温存する。

## 再現（Opus が確認済み）
`/tmp/pc` に次の局面を作り、`POKECHAMP_LOGS=/tmp/pc python3 battle.py auto --me アシレーヌ --opp ルカリオ --hp 85/187 40 --sec 8 --packet` を実行すると `次: ミミッキュに交代` になる。
- `current.json`: my_order = アシレーヌ / ミミッキュ / ガブリアス、opp_team = ルカリオ / カバルドン / ガブリアス / サーフゴー / ドヒドイデ / アーマーガア
- `live/field_state.json`: active = アシレーヌ と ルカリオ。自分のガブリアスは瀕死。相手のルカリオは mega=True、moves_seen=["ラスターカノン"]。mega_used = 自分 False、相手 True。そのほかのキーは `logs/sessions/20261017_2100/field_state.json` と同じ形にする。

出力の PACKET:
- `threat` に **てっていこうせん 67-79% 1発100%** が入っている。相手が実際に撃った技はラスターカノン（39-45%、1発6%）だけ。
- `opp_set` の候補はどれも記事由来で、**ラスターカノンを含まない**（てっていこうせん・はどうだん・あくのはどう・しんくうは）。それでも確率は p=0.12 で「不明」のまま使われている。
- 評価は `ミミッキュに交代 -23.66` に対して `ムーンフォース -58.92`。相手に先手のてっていこうせんで落とされる前提なので、ばけのかわで受けるミミッキュ交代が上位に来ている。

## 原因
1. **見えた技と、仮定した相手の型が食い違っている（主因）**
   `battle.py` で相手の型を作る処理（`opp_sets` → `infer.best_set` / `known_set`、および `m.moves = [mv] + m.moves[:3]`）は、見えた技を先頭に足して末尾の技を押し出すだけ。
   その結果、ラスターカノンを撃った相手が、同じはがね・特殊のてっていこうせんも持っている前提になる。
   さらに、ラスターカノンを含まない記事の型が候補から外れず、`threat` と探索がその型で計算されている。
2. **自分の交代を認識できていない**
   自分の交代は、メッセージが「ゆけっ！」だけで名前が読めず、自分の場のポケモンが更新されない。
   そのため交代の後も前のポケモンが場にいる前提で再計算し、同じ交代や逆向きの交代を勧め直す。
   ログの例: `logs/sessions/20261017_2100/` の #83→#84、#88→#89、#178→#179。
3. **交代の往復を抑える仕組みがない**
   評価値の差がわずかでも交代を出す。前のターンに出したポケモンへすぐ戻す提案も止めていない。

## 修正要件

### R1 見えた技と型の整合（battle.py / infer.py）
- R1-1 相手が実際に使った技（`moves_seen`）を含まない型は、候補から外す。どの候補にも含まれない場合だけ、R1-2 で技を差し替えた型を使う。
- R1-2 見えた技を型に足すときは、**同じタイプ・同じ分類（物理/特殊）の技**を差し替える。無ければ同じ分類で威力が最も低い攻撃技、それも無ければ末尾の技を差し替える。対象は `m.moves` だけでなく、メガ後の形（`BM` の mega 側の技）にも同じ処理をする。
- R1-3 同じタイプ・同じ分類の攻撃技を2つ持つ型は、出典（`known_set`、記事、使用率データ）がその2つを明示している場合だけ認める。
- R1-4 PACKET の `threat` と `opp_set` は、R1-1〜R1-3 を適用した後の型から作る（表示と探索の前提を一致させる）。

### R2 自分の交代の認識（game_watch.py / msgparse.py）
- R2-1 直前の判断が「Xに交代」で、そのターンのメッセージに自分側の「ゆけっ」「戻れ」「行け」「頼んだ」などが出たら、自分の場を X にする。
- R2-2 自分のHPパネルから最大HP（「114/187」の 187）を読み、選出した3体の最大HPと照合して自分の場を決める。3体の最大HPは `team.py` から計算する。同じ値が2体いるときは名前の読み取りで決める。R2-1 と食い違ったら R2-2 を優先する。
- R2-3 自分の場が変わったら `field_state.json` の `active.me` を更新し、ログに `{'side':'me','switch_seen':...,'from':'maxhp'|'advice'}` を残す。

### R3 交代の往復を抑える（battle.py の判断の最後）
- R3-1 交代以外の最善手との評価差が小さい（目安: 評価値の幅の 3% 未満、または 2.0 未満）ときは、交代を出さずに技を出す。
- R3-2 前のターンに場から引いたポケモンへ戻す交代は、評価差が十分大きい（目安: 5.0 以上）場合だけ出す。
- R3-3 「勝てる対面」を優先する。自分が技を出せば相手を確定で倒せる（ko が 1発100%、または相手より先に動いて落とせる）。かつ、相手が**実際に見せた技**では自分が落ちない（被ダメ最大が残りHP未満）。この2つを満たすとき、交代は出さない。見えていない技（R1 で候補に残る技）による確率的なリスクは、評価値の比較に任せる。

## 受け入れ条件
1. 上の再現局面で `次: ムーンフォース` を出す。`threat` にてっていこうせんが出ない（ラスターカノンは残る）。
2. 同じ局面で自分のHPを `30/187` に下げる（ラスターカノンで落ちうる）と、ミミッキュへの交代、またはアクアジェット等の別の判断を出してよい。ただし、例外やエラーで落ちない。
3. `logs/sessions/20261017_2100/` の `battle_messages.jsonl` を R2 の処理で再生したとき、#84 の時点で自分の場が ヒートロトム、#180 の時点で メタグロス になる（ログに自分側の交代として記録されていること）。実際の画面データが足りず確認できない分は、確認できなかった理由を報告する。
4. 既存の動作確認が通る（`python3 -m py_compile` が全ファイルで通る、`battle.py select` と `battle.py auto` が上の再現局面以外でも例外を出さない）。
5. 判断にかかる時間が今より増えない（`--sec 8` で 10 秒以内）。

## 対象外
- 画像AI（SPEC_VISION の A）と字体照合（同 B）には触れない。
- 相手の型データ（`data/*.json`）の中身は書き換えない。読み方だけを直す。

## 改訂（ユーザー指示: 型の想定は排除せず、見えた行動を確率の根拠にする）
- R1-1〜R1-3（同じタイプ・分類の技を型から外す）は**取り下げ**。夜間学習などで取り込んだ型に2つ以上あれば残す（ラスターカノン＋てっていこうせん、はめつのひかり＋ムーンフォース、ウェーブタックル＋アクアジェット＋クイックターン など）。
- 代わりに `infer.likelihood` の `move` で次の軽い根拠を使う（どれも排除ではなく確率を下げるだけ）:
  - 見えた技が型に無い: ×0.5（型を書き換える必要がある）。
  - 見えた技と同タイプ・同分類・同優先度で、より威力の高い技を型が持つ（強い方を使わなかった）: ×0.6。優先度が違う技（アクアジェット）は対象外。
- `force_moves`（見えた技を型に入れる処理）は、同タイプの技を狙って外さず、使用率が最も低い未判明の技を外す。
- R3-3 は「見せた技で落ちない」に加え、**相手が持ちうる型全体のうち、こちらを先に落とせる技を持つ型の確率が35%以下**のときだけ交代せず攻撃する。
